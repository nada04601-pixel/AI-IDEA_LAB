# 008. 위탁판매 자동화 (도매처 → 오픈마켓 상품 등록·자동 발주)

- 상태: **구상 단계** (핵심 로직 프로토타입 CLI 있음, 실제 API 키로는 검증 전)
- 프로젝트 코드: [projects/008-dropship-automation](../../projects/008-dropship-automation)
- 작성일: 2026-10-23
- 프로젝트 유형: 미정 — 지금은 개인용 CLI, 이후 설치형 데스크톱 앱 또는 SaaS (5장)

---

## 1. 개요

도매처(도매매) 상품을 찾아 오픈마켓(네이버 스마트스토어)에 자동으로 등록하고, 주문이 들어오면 도매처에 **고객 배송지로 자동 발주**하는 위탁판매(드롭쉬핑) 자동화.

```
[소싱]  도매처 검색 → 규칙으로 고르기(가격·재고·제외 낱말) → 판매가 계산 → 오픈마켓 등록
[주문]  오픈마켓 결제 완료 주문 → 안전장치 확인 → 도매처 주문서 생성(고객 배송지) → 오픈마켓 발주 확인
```

- **해결하려는 문제:** 위탁판매자는 도매 사이트에서 상품을 하나씩 옮겨 등록하고, 주문이 올 때마다 주소를 복사해 도매처에 직접 주문해야 한다. 상품 수와 주문이 늘수록 시간이 들고 실수(오배송·중복 발주·역마진)가 생긴다.
- **예상 사용자:** 스마트스토어·쿠팡에서 도매매 상품을 위탁판매하는 1인 셀러.
- **확장 방향:** 판매처에 쿠팡, 공급처에 다른 도매 사이트를 추가. 이후 송장 연동, 가격·재고 동기화.

## 2. 비슷한 서비스 (시장)

| 방식 | 예시 | 특징 |
|---|---|---|
| 웹 SaaS (통합관리) | 사방넷, 플레이오토, 샵링커 | 설치 없이 로그인. 수백 개 쇼핑몰 주문 수집·상품 등록·재고 관리 |
| 웹 + 크롬 확장 (수집형) | 윈들리 | 도매 사이트에서 클릭으로 상품 수집 → 가공 → 등록 |
| 위탁판매 특화 | UOS 등 | 여러 오픈마켓 주문 수집 + 도매처 구매 |
| 맞춤 제작 | 크몽 외주 | 공식 API 연동 + 엑셀/시트·예약 실행, 판매자 1명 전용 |

기능 범위: 상품 수집·가공 → 대량 등록 → 주문 수집·도매처 발주 → 송장 연동 → 가격·재고 동기화 → 정산·통계.
프로토타입은 앞의 세 단계를 다룬다.

검색 키워드: 위탁판매 자동화 프로그램, 스마트스토어 대량등록 프로그램, 오픈마켓 통합관리 솔루션, 주문수집 자동화, 송장 자동 등록, 도매매 자동발주, 네이버 커머스API, 커머스 솔루션 등록, 쿠팡 오픈API(WING), dropshipping automation, multichannel listing software, SaaS 멀티테넌트, 스마트스토어 위탁판매 제재, 위탁판매 상세페이지 저작권, 통신판매업 신고.

## 3. 외부 API와 제약

### 3.1 네이버 커머스API (판매처)
- OAuth2 client_credentials + 전자서명(bcrypt(client_id_timestamp, client_secret) → Base64), 토큰 3시간
- 상품: 이미지 업로드(`/v1/product-images/upload`) → 상품 등록(`/v2/products`)
- 주문: 변경 상품 주문 내역(`last-changed-statuses`, 24시간 단위) → 상세 조회(`product-orders/query`, 배송지 포함) → 발주 확인(`confirm`) → (다음 단계) 발송 처리(`dispatch`)
- **가장 큰 제약: 애플리케이션에 등록한 "API 호출 IP"에서만 호출 가능.** GitHub Actions·Cloudflare처럼 IP가 바뀌는 곳에서는 못 돌린다

### 3.2 도매꾹/도매매 OpenAPI (공급처)
- 상품리스트 v4.1(`market=supply`가 도매매), 상품상세 v4.6(옵션은 `selectOpt` JSON), 로그인 v4.1(sId), 주문서 생성 v4.3(`setOrder`)
- 주문은 **사업자 회원 + Private API 승인** 필요, **현금성 이머니에서 바로 결제**
- 문자열은 EUC-KR 범위만 가능(예: "똠" 불가) → 이름·주소는 고치지 않고 보류
- 오류는 HTTP 200 + `errors` 객체. `DB_INSERT_ERROR`는 일부만 주문됐을 수 있음

### 3.3 쿠팡 (확장 예정)
- 판매자가 WING에서 Open API 키 발급. IP 제한 여부는 연동 전에 확인 필요

## 4. 프로토타입 설계 (projects/008)

- Node 22 + TypeScript(빌드 없이 실행), SQLite(`node:sqlite`), 의존성은 bcryptjs 하나
- 샌드박스: `npm run sandbox -- …`(config.sandbox.json, data/sandbox/)로 실제 키 없이 전체 흐름 확인
- `SupplierAdapter`(search, getProduct, purchase) / `MarketAdapter`(uploadImages, registerProduct, fetchPaidOrders, getOrderLines, confirmOrders) 인터페이스로 분리 → 쿠팡·다른 도매처는 어댑터만 추가
- **주문 ↔ 도매처 상품 연결:** 판매자 관리 코드 = `domeme:<상품번호>`, 옵션 관리 코드 = 도매매 옵션 코드. 주문에 그대로 돌아와 별도 매핑표가 필요 없음
- **안전장치:** 중복 발주 방지, 응답 불명 시 자동 재발주 금지(unknown), 공급가 상승·역마진·금액 한도 보류(held), 사람 승인(approve) 후 재처리, 기본은 미리 보기(`--live`일 때만 실제 실행)

## 5. 제품 형태 (미결정)

| | 설치형 데스크톱 앱 | 웹 SaaS |
|---|---|---|
| 개인정보·키 보관 | 사용자 PC에만 → 부담 작음 | 내 서버에 보관 → 암호화·약관·개인정보 처리방침 필수 |
| 네이버 IP | 사용자 PC의 공인 IP 등록. 가정용 IP가 바뀌면 재등록 필요(감지·안내 기능 필요) | 서버 고정 IP 한 번. 서버를 늘려도 나가는 IP는 하나로 고정(NAT/고정 IP) |
| 실행 | PC가 켜져 있어야 함(꺼진 동안 주문은 켜질 때 처리) | 항상 실행 |
| 배포·운영 | 업데이트 배포, 백신 경고(코드 서명), PC별 문제 | 서버·DB 운영, 회원·결제 |
| 만드는 양 | 지금 코드 + 화면(Electron 등) | 지금 코드 + 서버·웹 화면·회원·결제·멀티테넌트 |

**SaaS에서 네이버 연동 방식**
1. 판매자마다 커머스API센터에 애플리케이션을 만들고 내 서버 IP를 등록한 뒤 ID·시크릿을 입력 — 심사 없이 바로 시작, 대신 가입 과정이 번거롭고 시크릿을 보관해야 함
2. **커머스 솔루션 사업자 등록** — 판매자는 솔루션 연동만 하고, 토큰은 `type=SELLER` + 판매자 ID로 발급. 큰 통합관리 서비스들의 방식. 네이버 심사·요건 확인 필요

**도매매는 SaaS라도 판매자 각자의 사업자 계정·이머니로 주문**해야 해서 아이디·비밀번호를 보관해야 한다(가장 민감). 대량 연동이면 도매꾹 기술지원(techsupport@ggook.com)에 제휴 방식 문의.

현재 생각: 본인이 먼저 쓰는 단계는 설치형, 판매가 목적이면 SaaS(1번으로 시작 → 사용자가 늘면 2번).

## 6. 로드맵

1. (완료) 프로토타입 CLI: 검색·등록·주문 발주·발주 확인, 단위 테스트
2. (완료) M1 샌드박스: 가짜 판매처·도매처(`fake`)로 키 없이 로컬에서 소싱 → 주문 → 발주 → 발주 확인, 실패 상황(거절·응답 없음·역마진·공급가 상승·취소) 재현
3. 실제 키로 검증: 상품 1개 등록 → 지인 주문 1건으로 발주까지 확인(본인 구매는 가구매로 볼 수 있음)
4. 제품 형태 결정(5장)
5. 송장 연동: 도매매 구매 주문서 조회 → 스마트스토어 발송 처리
6. 가격·재고 동기화, 품절 시 판매 중지
7. 취소·반품 연동, 같은 주문 묶음 발주, 알림
8. 쿠팡 판매처 어댑터

## 7. 리스크

- 오픈마켓 정책: 대량 등록·중복 상품은 제재 대상이 될 수 있음. 공식 API만 사용(매크로 금지)
- 상세페이지 저작권·상표: 도매처가 허락한 범위에서 사용, 인증 필요 품목(건강기능식품·전기용품 등)은 제외
- 원산지·KC 인증 등 카테고리별 필수 항목
- 역마진·품절·가격 변동 → 안전장치로 보류
- 통신판매업 신고 등 판매자 의무

## 8. 미결정 사항

- 제품 형태: 설치형 / SaaS
- SaaS라면 네이버 연동 방식(판매자 직접 등록 / 솔루션 사업자)과 서버 위치
- 같은 주문의 여러 상품을 한 주문서로 묶을지
- 수익 모델(구독, 주문당 수수료 등)
