## 1. 프로젝트 개요

AI Shorts Studio는 사용자가 쇼츠 주제를 입력하면 대본과 장면 구성을 만들고, 장면별 이미지·영상 및 음성을 생성한 뒤, 사용자가 각 장면을 승인하거나 반려하고, 최종적으로 세로형 MP4 영상을 내보낼 수 있게 하는 웹 애플리케이션이다.

핵심 원칙은 **장면별 검토·승인을 거치는 반자동 제작**이다. 생성 결과를 무조건 자동 합성하지 않고, 사용자가 장면별로 확인하고 재생성할 수 있어야 한다.

## 2. 개발 및 비용 원칙

1. 개인 프로젝트로 개발한다.
2. 업무용 Haicode는 사용하지 않는다.
3. 무료 또는 저비용 도구와 API를 우선한다.
4. 유료 API 호출이나 결제를 사용자 승인 없이 수행하지 않는다.
5. API 키와 비밀번호를 소스 코드에 하드코딩하지 않는다. 환경 변수와 `.env`를 사용하고 `.env`는 Git에 올리지 않는다.
6. 공급자별 AI 기능은 어댑터 구조로 분리해 추후 교체할 수 있게 한다.
7. 초기 버전은 로컬 개발·로컬 파일 저장을 우선한다.
8. 구현은 작은 단계로 나누고 각 단계에서 실행·테스트 가능한 상태를 유지한다.
9. 기존 파일을 수정하거나 삭제하기 전 변경 계획을 설명하고 승인을 요청한다.
10. 요청된 범위를 넘어서는 기능을 임의로 추가하지 않는다.

## 3. MVP 범위

### 포함 기능

- 프로젝트 생성, 목록 조회, 상세 조회, 수정, 삭제
- 프로젝트별 제목, 주제, 목표 길이, 화면 비율, 스타일 등 기본 설정
- 주제에서 대본 초안 생성
- 대본을 장면 단위로 분리하고 장면 순서 관리
- 장면별 대사, 화면 설명, 이미지/영상 프롬프트 편집
- 캐릭터 및 시각적 일관성에 필요한 참조 정보 관리
- 장면별 이미지 생성 작업
- 지원되는 외부 서비스가 설정된 경우 장면별 영상 생성 작업
- 장면 상태 관리: 초안, 생성 대기, 생성 중, 검토 필요, 승인, 반려, 실패
- 장면별 승인, 반려 사유 입력, 재생성 요청
- 작업 상태와 오류 메시지 확인 및 실패 작업 재시도
- 비용이 발생할 수 있는 작업의 예상/실제 비용 기록(가능한 경우)
- 음성/TTS 생성 인터페이스
- 자막 생성 및 타이밍 데이터 관리
- FFmpeg를 이용한 장면 합성, 음성·자막 결합 및 MP4 렌더링
- 최종 결과 미리보기 및 로컬 파일 다운로드/내보내기
- 로컬 프로젝트 파일 및 생성 자산 관리

### MVP에서 제외

- 자동 YouTube 업로드
- 다중 사용자, 팀 협업, 역할 권한
- 결제, 구독, 과금 시스템
- 클라우드 스토리지 필수화
- 복잡한 타임라인 편집기
- 무인 완전 자동 제작 파이프라인
- 유료 API를 기본값으로 강제하는 설계

| 구분 | 선택 |

| 백엔드 | Python + FastAPI |
| 데이터베이스 | SQLite |
| 파일 저장 | 로컬 파일 시스템 |
| 영상 렌더링 | FFmpeg |
| AI 연동 | 공급자별 인터페이스/어댑터로 분리 |

기술 스택은 프로젝트 상태를 먼저 확인한 뒤 적용한다. 기존 프로젝트가 이미 시작된 경우, 현재 구조를 무조건 덮어쓰지 말고 차이와 변경 계획을 먼저 보고한다.

## 5. 사용자 흐름

1. 사용자가 새 프로젝트를 만든다.
2. 주제, 영상 길이, 화면 비율(기본 9:16), 분위기/스타일을 입력한다.
3. 대본 초안을 생성하고 사용자가 편집한다.
4. 대본을 장면별 스토리보드로 분리한다.
5. 각 장면의 대사, 설명, 프롬프트를 검토한다.
6. 장면별 이미지 또는 영상 생성 작업을 실행한다.
7. 사용자는 생성 결과를 확인해 승인하거나 반려한다.
8. 반려된 장면은 사유를 반영해 수정·재생성한다.
9. 필요한 장면이 승인되면 음성, 자막, 효과음 등 후반 작업을 진행한다.
10. FFmpeg로 최종 세로형 MP4를 렌더링한다.
11. 사용자가 결과를 미리 보고 파일로 내보낸다.

## 6. 주요 화면

1. **대시보드:** 프로젝트 목록, 진행 상태, 최근 작업, 오류/대기 작업
2. **프로젝트 생성/설정:** 주제, 길이, 비율, 스타일
3. **대본 편집기:** 대본 초안 생성 및 수정
4. **스토리보드:** 장면 목록, 순서, 대사, 장면 설명, 프롬프트
5. **장면 검토 화면:** 생성 결과 미리보기, 승인, 반려, 재생성
6. **작업 상태 화면:** 진행 상태, 오류, 재시도, 비용 기록
7. **렌더링/내보내기 화면:** 출력 설정, 렌더링 진행 상태, MP4 미리보기 및 내보내기

REST API 예시이며, 구현 전에 기존 구조와 일관성을 확인한다.

| 메서드 | 경로 | 설명 |

## 9. 장면 상태 및 승인 규칙

- 장면은 검토 가능한 결과가 준비되면 `review_required` 상태가 된다.
- 사용자가 승인하면 `approved`로 전환한다.
- 반려 시 사유를 저장하고 `rejected`로 전환한다.
- 반려 장면을 재생성하면 이전 자산을 무조건 삭제하지 말고 버전을 구분하거나 이력을 보존한다.
- 최종 렌더링은 필수 장면이 모두 승인된 경우에만 실행한다. 예외를 허용한다면 사용자에게 명확히 표시한다.
- 작업 실패 시 오류 메시지를 저장하고 사용자가 재시도할 수 있어야 한다.
- 중복 클릭이나 네트워크 재시도로 동일한 유료 작업이 무심코 여러 번 실행되지 않도록 확인 장치가 필요하다.

## 11. 단계별 개발 계획

### 0단계 — 저장소 점검 및 계획

- 현재 폴더, Git 상태, 설치된 도구, 기존 파일을 확인한다.
- 요구사항과 현재 상태의 차이를 요약한다.

- 이 단계에서는 파일을 수정하거나 패키지를 설치하지 않는다.

### 1단계 — 기본 뼈대와 프로젝트 관리

- Next.js + TypeScript 프런트엔드 기본 화면
- FastAPI 백엔드 기본 앱 및 상태 확인 엔드포인트
- SQLite 연결
- 프로젝트 CRUD
- 기본 화면과 API의 연결
- 실행 방법 문서화 및 기본 테스트

### 2단계 — 대본과 스토리보드

- 프로젝트 설정 편집
- 대본 생성용 provider 인터페이스
- 장면 목록 생성·수정·정렬
- 장면별 대사/설명/프롬프트 편집
- 외부 AI 키가 없어도 테스트 가능한 mock provider

### 3단계 — 장면 생성 및 승인

- 이미지/영상 provider 어댑터
- 장면별 생성 작업과 상태 표시
- 미리보기, 승인, 반려 사유, 재생성
- 실패 작업 재시도
- 비용 기록 및 유료 작업 전 확인

### 4단계 — 음성, 자막, 렌더링

- TTS provider 인터페이스
- 자막 생성/저장
- FFmpeg 설치 확인 및 렌더링 파이프라인
- 9:16 MP4 출력
- 렌더링 오류 처리, 미리보기 및 내보내기

### 5단계 — 안정화

- 주요 흐름 테스트
- 잘못된 입력 및 실패 상황 처리
- 비용·작업 상태 표시 개선
- README와 사용자 실행 가이드 완성

## 12. 완료 기준

- 로컬에서 프런트엔드와 백엔드를 실행할 수 있다.
- 프로젝트를 만들고 다시 열어도 데이터가 유지된다.
- 프로젝트의 장면을 생성/수정/정렬할 수 있다.
- 장면을 승인·반려하고 반려 사유를 확인할 수 있다.
- AI 키가 없는 상태에서도 mock provider로 주요 흐름을 테스트할 수 있다.
- 실제 외부 AI 기능은 공급자 설정 및 비용을 사용자에게 알린 뒤 사용할 수 있다.
- 렌더링 가능한 승인 장면으로 최종 MP4를 생성하고 로컬로 내보낼 수 있다.
- 설치·실행·테스트 방법이 README에 기록되어 있다.

## 13. CLI 코딩 에이전트 작업 규칙

이 문서를 프로젝트 요구사항의 기준으로 사용한다.

1. 먼저 현재 작업 디렉터리와 파일 구조를 분석한다.
2. README.md, 기존 설정, Git 상태를 확인한다.
3. 요구사항과 기존 코드 사이의 차이 및 위험을 요약한다.
4. 변경 전에 계획과 변경 대상 파일을 제시한다.
5. 초기 점검 단계에서는 파일 수정, 삭제, 패키지 설치, 외부 API 호출을 하지 않는다.
6. 사용자의 승인을 받은 후에만 승인된 범위의 변경을 수행한다.
7. 매 작업 후 변경 파일, 실행 명령, 테스트 결과, 미해결 문제를 보고한다.
8. 실패한 테스트를 성공했다고 표현하지 않는다.
9. 비밀키를 출력하거나 커밋하지 않는다.
10. 유료 API 호출, 유료 플랜 가입, 클라우드 리소스 생성은 명시적 승인 없이 하지 않는다.
11. 업무용 Haicode를 사용하지 않는다.
12. 불확실한 요구사항은 임의로 결정하지 말고 질문하거나 선택지를 제시한다.

## 14. CLI에 처음 입력할 프롬프트

다음 내용을 코딩 CLI에 그대로 붙여 넣는다.

> 현재 작업 디렉터리를 분석하고, AI Shorts Studio — 요구사항 및 CLI 작업 지침 문서를 기준으로 프로젝트의 현재 상태를 점검해 줘.
>
> 이번 단계는 분석 전용이다. 파일을 생성·수정·삭제하지 말고, 패키지를 설치하지 말고, 외부 API를 호출하지 마.
>
> 1. 현재 디렉터리와 파일 구조를 확인한다.
> 2. Git 상태와 기존 설정 파일을 확인한다.
> 3. Node.js, npm, Python, FFmpeg가 사용 가능한지 확인한다. 확인할 수 없는 항목은 그렇게 표시한다.
> 4. 요구사항에 비추어 현재 구현된 것과 미구현인 것을 구분한다.
> 5. 기존 파일을 덮어쓰지 않는 최소 변경 계획을 제안한다.
> 6. 무료/mock 모드부터 시작할 수 있도록 계획한다.
> 7. 실행할 명령, 변경할 파일, 예상 위험을 정리하고 사용자 승인을 기다린다.
>
> 유료 API 호출/결제 금지, API 키 하드코딩 금지, 업무용 Haicode 사용 금지. 승인 없이 어떤 파일도 변경하지 마.

## 15. 구현 전 확인 사항

- 운영체제와 설치된 Node.js/Python 버전
- FFmpeg 설치 여부
- 현재 저장소가 비어 있는지, 기존 코드가 있는지
- 대본/이미지/영상/TTS 공급자 선택 여부
- 외부 AI 없이 mock provider로 시작할지 여부

이 항목들은 초기 점검 단계에서 확인하고, 불필요한 설치나 지출 없이 진행한다.
