# 개발계획서

> 기준 문서: `idea.md`, `requirements.md`, `features.md`, `screens.md`, `database.md`, `api.md`
> 개발자: 1인 (Claude Code 등 AI 도구 활용) (가정)
> `(가정)` 표시는 확인 전 임시 결정이다. 라이브러리와 프레임워크 버전은 프로젝트 생성 시점의 최신 안정 버전을 확인해서 정한다.

## 1. 개발 원칙

1. **AI 없이 동작하는 뼈대를 먼저 만든다.** 업로드 → 분석 → 정규화 → 집계 → 보고서 생성이 규칙 매핑만으로 끝까지 동작한 뒤에 AI 매핑을 붙인다. AI가 틀리거나 장애가 나도 서비스가 동작한다는 것을 처음부터 보장한다.
2. **세로로 자른다(Vertical Slice).** 백엔드만 다 만들고 프론트를 만드는 대신, 기능 묶음마다 API와 화면을 같이 완성한다. 매 단계 끝에 직접 눌러볼 수 있어야 한다.
3. **계산은 테스트로 증명한다.** 날짜, 금액, 집계, 합계 검증은 단위 테스트를 먼저 작성한다. 이 서비스는 숫자가 틀리면 끝이다.
4. **실제 양식과 실제 데이터로 검증한다.** 첫 완성 시점에 수작업 결과와 100% 일치하는지 비교한다. (`idea.md` 성공 기준)
5. **문서가 기준이다.** AI에게 구현을 맡길 때는 항상 해당 문서(`features.md`의 F-xxx, `api.md`의 A-xx)를 먼저 읽게 한다.

## 2. 기술 스택

| 영역 | 선택 | 선택 이유 |
|---|---|---|
| 언어 | Java (최신 LTS) | 익숙한 언어, `BigDecimal`로 금액 계산, AI가 만든 코드를 직접 검토 가능 |
| 백엔드 | Spring Boot (최신 안정 버전) | 익숙한 프레임워크 |
| 보안 | Spring Security (세션 + CSRF) | `api.md`의 HttpOnly 세션 쿠키 방식 |
| Excel | Apache POI | 기존 양식의 서식을 유지하면서 값 입력 |
| CSV | Commons CSV 또는 OpenCSV + 인코딩 감지 | UTF-8, CP949 자동 판별 |
| DB | PostgreSQL | `database.md`의 JSONB, UUID 사용 |
| 마이그레이션 | Flyway | `database.md`의 DDL을 버전 관리 |
| 데이터 접근 | MyBatis (가정) | `database.md`가 SQL 중심이고 JSONB 쿼리를 직접 다루기 쉬움. 익숙한 쪽(JPA 포함)을 써도 무방 |
| AI | Claude API (HTTP 호출 또는 공식 SDK) | 컬럼 매핑 한 곳에서만 사용. 소형 모델로 시작해 정확도를 측정한 뒤 조정 |
| 비동기 | Spring `@Async` + DB 상태값 | 보고서 생성 1종류뿐이라 별도 메시지 큐 불필요 |
| 프론트 | Vue 3 + Vite + TypeScript | `api.md`의 JSON API를 그대로 사용 |
| 프론트 상태 | Pinia, Vue Router | 마법사 상태 관리, 화면 이동 |
| UI 라이브러리 | 1개 선택 (Element Plus 또는 PrimeVue, 가정) | 표, 드롭다운, 업로드, 단계 표시 컴포넌트 제공 |
| 파일 저장 | `FileStorage` 인터페이스 + 로컬 디스크 구현 | 이후 S3 호환 저장소로 교체 가능 |
| 테스트 | JUnit 5, Testcontainers(PostgreSQL), Vitest | DB를 포함한 통합 테스트 |
| 배포 | Docker (앱 1개 + PostgreSQL) | 프론트 빌드 결과를 Spring 정적 리소스로 포함해 한 개의 jar로 배포 |

### 프론트 배포 방식

- 개발 중: Vite 개발 서버(5173)가 `/api`를 Spring(8080)으로 프록시한다.
- 배포 시: `vite build` 결과를 Spring Boot의 정적 리소스에 포함한다. **같은 출처(Same-Origin)** 이므로 CORS 설정이 필요 없고, 세션 쿠키와 CSRF 처리가 단순해진다. (`api.md` 11장)

## 4. 핵심 설계 결정

### 4-1. Excel 처리 (`analysis/`, `report/`)

| 항목 | 결정 |
|---|---|
| 읽기 | 이벤트(SAX) 방식 스트리밍으로 읽는다. 50,000행, 10MB 제한 안에서도 메모리 사용을 안정적으로 유지하기 위해서다. |
| 양식 입력 | 템플릿을 복사한 뒤 `XSSFWorkbook`으로 열어 셀에 값을 입력한다. 결과는 집계된 소량 데이터라 메모리 부담이 작고, 서식을 보존하는 데는 이 방식이 안전하다. |
| 수식 | 원본의 수식 셀은 **계산된 값**만 읽는다. 매크로(.xlsm)와 외부 링크는 읽지 않는다. |
| 보안 | 압축 폭탄(zip bomb) 방지를 위해 POI의 압축 해제 한도 설정을 켜고, XML 외부 엔티티(XXE)를 차단한다. 업로드 시 파일 시그니처를 검사한다. (`api.md` A-08) |
| 헤더 행 감지 | 위에서부터 "비어 있지 않은 셀이 많고 대부분 문자열"인 첫 행을 후보로 하고, 실패하면 사용자가 지정한다. |
| 병합 셀 | 감지해서 경고만 한다. 자동으로 풀어주지 않는다. (MVP) |

### 4-2. 금액, 날짜 정규화 (`normalization/`)

- **금액은 `BigDecimal`** 로만 다룬다. `double`, `float` 사용을 금지한다. 쉼표, 통화 기호, "원" 제거 후 변환하고, 실패하면 오류 행으로 보낸다.
- **날짜는 `java.time`** 으로 처리한다. 허용 형식 목록(`yyyy-MM-dd`, `yyyy.MM.dd`, `yyyy/MM/dd`, `yyyyMMdd` 등)을 순서대로 시도하고, Excel 날짜 시리얼 값도 변환한다. `2026-13-45` 같은 불가능한 날짜는 오류로 처리한다.
- 거래처명 정규화는 규칙(`(주)`, `㈜`, `주식회사`, 공백 제거) 기반으로 **통합 제안만 만들고 자동 적용하지 않는다.** (BR-06)

### 4-3. AI 연동 (`mapping/`, `ai/`)

```
MappingService
  ├─ HistoryMappingProvider   (이전 작업 매핑 재사용)
  ├─ ColumnMappingAdvisor     ← 인터페이스
  │    ├─ AiColumnMappingAdvisor    (Claude 호출)
  │    └─ RuleColumnMappingAdvisor  (컬럼명 유사도 + 타입 일치)
  └─ 결과 검증 → AI 실패 시 Rule로 대체 (fallback_used)
```

- AI에 보내는 페이로드는 서버가 `api.md` 9장 규격대로만 조립한다. **전체 행, 한 행의 값 조합은 보내지 않는다.** 이를 검증하는 단위 테스트를 반드시 둔다.
- 응답은 JSON 스키마로 검증한다. 형식 오류, 존재하지 않는 컬럼 번호, 중복 지정은 `invalid_response`로 기록하고 규칙 매핑으로 대체한다.
- 타임아웃 10초(가정). API 키는 환경 변수로만 주입하고 저장소에 넣지 않는다.
- 모든 호출은 `ai_call_logs`에 기록해서 비용과 실패율을 본다.
- **자동화 테스트에서는 실제 AI를 호출하지 않는다.** 응답 샘플(fixture)로 `AiColumnMappingAdvisor`의 파싱과 검증을 테스트하고, 실제 호출은 수동 확인용 별도 테스트로 분리한다.

### 4-4. 작업 단계 관리 (`job/`)

- `JobStepGuard` 한 곳에서 `api.md` 4장의 사전 조건과 초기화 규칙을 구현한다. 각 서비스가 흩어져서 검사하지 않는다.
- 앞 단계 변경 시 초기화는 트랜잭션 안에서 처리한다. (매핑, 오류 행, 통합 규칙, 중간 파일을 함께 정리)

### 4-5. 보고서 생성 비동기 처리 (`report/`)

- `POST /generate` → `status = generating`으로 저장 후 전용 스레드 풀(`ThreadPoolTaskExecutor`)에서 실행하고, `202`를 즉시 응답한다.
- 서버가 재시작되어 `generating`으로 남은 작업은 시작 시점에 `failed`(`SERVER_RESTARTED`)로 정리한다. 영원히 "생성 중"으로 남는 것을 막는다.
- 동시 실행 수에 상한을 둔다. (예: 4개, 가정)

### 4-6. 오류 처리 (`common/`)

- `ErrorCode` enum 하나에 `api.md` 10장의 코드, HTTP 상태, 사용자 메시지를 모은다.
- `@RestControllerAdvice`에서 `api.md` 2장의 오류 응답 형식으로 변환한다.
- 타인의 `job`, `file`은 `404`로 응답한다. 소유권 검사는 조회 쿼리에 `user_id` 조건을 넣는 방식으로 구현해서 누락을 막는다.

### 4-7. 프론트 (`frontend/`)

- **서버가 진실의 원천(source of truth).** 마법사 진행 상태는 서버의 `current_step`을 기준으로 하고, 화면은 새로고침해도 `GET /jobs/{id}`로 복구한다.
- `api/` 폴더에 A-01 ~ A-23 호출 함수를 만들고, 공통 래퍼에서 CSRF 헤더, 401 처리(로그인 화면 이동), 오류 메시지 표시를 처리한다.
- 라우트 구성

| 경로 | 화면 |
|---|---|
| `/login` | S-01 |
| `/` | S-08 이력 목록 (홈) |
| `/jobs/new` | S-02 |
| `/jobs/:id/template` | S-03 |
| `/jobs/:id/data` | S-04 |
| `/jobs/:id/mapping` | S-05 |
| `/jobs/:id/normalization` | S-06 |
| `/jobs/:id/result` | S-07 |
| `/history/:id` | S-09 |

- 라우터 가드: `current_step`보다 뒤 단계 URL로 직접 접근하면 도달 가능한 최대 단계로 이동시킨다.

## 7. AI 개발 도구 활용 방식

### 7-1. 작업 흐름

1. 구현할 단위를 문서 ID로 지정한다. 예: "F-003과 A-11을 읽고 `analysis` 패키지에 구현해줘. 인수 조건을 테스트로 먼저 작성해줘."
2. AI는 **문서에 없는 기능을 추가하지 말고 먼저 질문**한다. (`features.md`의 "범위 밖" 존중)
3. 구현 후 테스트를 실행하고, 결과를 직접 확인한다. 계산, 보안, 권한 코드는 사람이 직접 리뷰한다.
4. 완료한 기능은 `features.md`의 상태를 갱신하고 커밋한다. 커밋 단위는 기능 1개 (예: `F-003 데이터 분석 구현`).

### 7-2. `CLAUDE.md` 초안

````markdown
# AI Excel 보고서 자동생성기

## 프로젝트
Excel/CSV를 업로드하면 AI가 컬럼을 매핑하고, 지정된 Excel 양식으로 보고서를 생성하는 서비스.
문서는 docs/ 에 있다. 구현 전에 반드시 해당 문서를 먼저 읽는다.

## 문서 위치
- 기능 상세와 인수 조건: docs/features.md (F-xxx)
- 화면: docs/screens.md (S-xx)
- DB: docs/database.md / API: docs/api.md (A-xx)
- 규칙: docs/requirements.md (BR-01 ~ BR-09)

## 기술 스택
Java + Spring Boot, MyBatis, PostgreSQL, Flyway, Apache POI / Vue 3 + TypeScript

## 반드시 지킬 규칙
1. AI(LLM)는 컬럼 매핑 추천에만 쓴다. 집계, 날짜 변환, 셀 입력은 코드로 처리한다.
2. AI에는 컬럼명, 타입, 컬럼당 샘플 5개 이하만 보낸다. 전체 행을 보내는 코드를 만들지 않는다.
3. 금액은 BigDecimal. double/float 금지.
4. 모든 job/file 조회 쿼리에 user_id 조건을 넣는다. 타인의 리소스는 404.
5. 오류 응답은 api.md의 형식과 ErrorCode를 따른다.
6. 거래처 통합은 자동 적용하지 않는다. 사용자 확인 후에만 적용한다.
7. 문서에 없는 기능은 추가하지 말고 먼저 질문한다.
8. 실제 AI API를 호출하는 테스트를 자동 테스트에 넣지 않는다. fixture를 사용한다.
9. 로그에 파일 내용, 샘플 값, 비밀번호를 남기지 않는다.
10. API 키 등 비밀 값을 코드나 저장소에 넣지 않는다.

## 작업 방식
- 기능 1개 = 테스트 먼저 → 구현 → 테스트 통과 → features.md 상태 갱신 → 커밋
- DB 변경은 Flyway 마이그레이션 파일로만 한다. database.md도 함께 갱신한다.
- API를 바꾸면 docs/api.md도 같이 수정한다.
````

## 8. 기술 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 실제 보고서 양식이 복잡해서 셀 위치 정의가 어려움 | Slice 3 전에 실제 양식 확보. `cell_map` JSON을 양식 1종으로 먼저 검증하고 일반화는 미룬다. |
| 원본 Excel 형태가 다양함 (병합 셀, 제목 행, 숨김 열) | 샘플 파일 수집, 경고와 사용자 지정(헤더 행)으로 대응. 자동으로 해결하려 하지 않는다. |
| AI 매핑 정확도 부족 | 규칙 매핑 대체, 사용자 확인 필수, `ai_hint` 보강, 정확도 쿼리로 측정 후 모델/프롬프트 조정 |
| 대용량 파일로 메모리 부족 | 스트리밍 읽기, 10MB/50,000행 제한, 동시 생성 수 제한 |
| 한글 CSV 인코딩 오판 | UTF-8 엄격 검증 후 실패 시 CP949 시도. 샘플 파일로 회귀 테스트 |
| 합계 오차 | `BigDecimal` 사용, 집계 단위 테스트, 생성 전 합계 검증 필수 |
| 업로드 파일을 통한 공격 (압축 폭탄, XXE) | POI 압축 한도 설정, XXE 차단, 시그니처 검사, 사용자 파일명 미사용 |
| AI 호출 장애 | 타임아웃, fallback, 호출 한도 |
| 1인 개발의 범위 확장 | `features.md`의 "범위 밖"을 기준으로 거절. 추가 아이디어는 `inbox/ideas.md`로 보낸다. |
