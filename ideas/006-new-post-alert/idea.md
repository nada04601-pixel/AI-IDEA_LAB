## 1. 한 줄 설명

게시판 URL을 입력해 두면, 그 페이지에 **새 글이 올라올 때** 또는 **원하는 키워드가 들어간 제목의 글이 올라올 때** 바로 알려준다.

## 2. 해결하려는 문제

| 대상 | 겪는 불편 | 예시 |
|---|---|---|
| 수영장·체육센터 이용자 (첫 사용 사례) | 결원 추가 모집, 현장 접수 공지를 놓친다 | 구청·시설관리공단 공지사항에서 "결원", "추가모집", "수영" |
| 청약·임대 주택 대기자 | 공고 사이트를 매일 들어가 봐야 한다 | LH·SH 공고 게시판에서 "행복주택", "○○구" |
| 취업 준비생 | 기관마다 채용 게시판이 따로 있다 | 공공기관 채용 공지에서 "채용", "인턴" |
| 학부모 | 학교·유치원 공지를 늦게 본다 | 학교 홈페이지 가정통신문에서 "방과후", "신청" |
| 알뜰 소비자 | 핫딜·중고 매물을 계속 새로고침한다 | 핫딜 게시판에서 "에어팟", "무료배송" |

- 공공기관 게시판은 대부분 RSS나 알림 기능이 없다. 있어도 키워드로 걸러 주지 않는다.
- Visualping, Distill.io 같은 해외 웹페이지 변경 감지 서비스가 있다. 하지만 페이지 전체 변화를 감지해 알림이 잦고, 한국어 키워드·카카오톡 알림·관공서 게시판에 맞춰져 있지 않다. `(가정: 실제 사용감 비교 필요)`

## 3. 핵심 기능 (MVP)

1. **URL 등록:** 게시판 목록 페이지 주소를 붙여넣는다.
2. **목록 자동 인식:** 페이지에서 반복되는 "제목 + 링크" 묶음을 찾아 게시글 목록으로 인식한다. 인식 결과(최근 글 5개)를 보여주고 사용자가 "맞아요"를 눌러 확정한다.
3. **알림 조건 선택**
   - **모든 새 글:** 목록에 처음 보는 글이 나타나면 알린다.
   - **키워드 글만:** 제목에 키워드가 하나라도 들어가면 알린다(OR). 제외 키워드도 지정한다. 예: 포함 "수영, 결원" / 제외 "마감, 결과".
4. **확인 주기:** 기본 10분. 같은 URL을 여러 사람이 등록해도 서버는 한 번만 가져온다(URL 단위 캐시).
5. **알림:** 제목 + 게시판 이름 + 원문 링크. 누르면 원문 글로 바로 이동한다.
6. **알림 기록:** 받은 알림 목록, 감시 중인 URL 목록, 일시정지·삭제.

### 새 글 판단 방법

- 글마다 고유 키를 만든다: 글 링크(쿼리 정리 후) → 없으면 글 번호 → 없으면 제목 + 날짜.
- 직전에 본 키 집합과 비교해 **처음 보는 키만** 새 글로 본다. 고정 공지가 위아래로 움직이거나 페이지가 넘어가도 오알림이 나지 않게 한다.
- 처음 등록할 때 보이는 글은 기준선으로만 저장하고 알리지 않는다.
- 제목이 수정된 글은 새 글로 보지 않는다(같은 키).

### 하지 않을 것

- 로그인해야 보이는 게시판, 사용자 계정 정보 저장.
- 1분 미만의 짧은 간격으로 반복 요청하기.
- 글 본문을 복사해 다시 게시하기. 제목과 링크만 알린다.

## 4. 기술 판단

| 항목 | 선택 | 이유 |
|---|---|---|
| 페이지 가져오기 | 일반 HTTP 요청 + HTML 파싱 | 공공기관 게시판은 대부분 서버에서 그린 HTML이다 `(가정)` |
| 자바스크립트로 그리는 페이지 | 2단계에서 헤드리스 브라우저(Playwright) | 비용이 커서 필요한 URL만 사용 |
| iframe 게시판 | iframe 주소를 찾아 그 주소를 감시 | 관공서 게시판에 흔하다 |
| RSS가 있는 사이트 | RSS 우선 사용 | 가장 정확하고 서버 부담이 작다 |
| 수집 실행 | 처음엔 GitHub Actions 크론(005와 같은 방식, 최소 5분), 사용자가 늘면 작은 서버나 Cloudflare Workers Cron | 초기 비용 0원 |
| 화면 | Vue + PWA (003 마음기록과 같은 구성) | 재사용 |
| 알림 채널 | 웹 푸시(PWA) → 텔레그램 봇 → 카카오 알림톡(유료) | 무료 채널부터 시작 |

## 5. 확장 기능 (2단계 이후)

- **글자 변화 감지 모드:** 게시판이 아닌 페이지의 특정 부분에서 글자나 숫자가 바뀌면 알린다. 예: 강좌 목록의 "마감" → "접수중", 잔여 인원 0 → 1. 원래 아이디어였던 **수영장 취소 자리 감지**는 이 모드로 다룬다.
- **추천 감시 묶음:** "우리 동네 수영장 결원 공지", "LH 임대 공고", "○○구청 채용"처럼 미리 설정한 URL + 키워드를 첫 화면에서 한 번에 추가한다.
- **AI 요약:** 알림이 온 글 본문을 3줄로 요약한다. 신청 기간·대상·방법만 뽑는다.
- **공개 모음 페이지:** 관공서 공지 중 많이 감시하는 키워드의 새 글을 모아 보여준다(검색 유입).

## 6. 수익화

- 무료: URL 3개, 10분 간격, 웹 푸시.
- 유료(월 1,000~3,000원 `(가정)`): URL 수 확대, 5분 간격, 카카오 알림톡, 자바스크립트 페이지 지원.
- 추천 감시 묶음과 공개 모음 페이지로 검색 유입 + 광고(002 노바랩 계산소 모델).

> 판단 (2026-10-08): 범용 "URL + 키워드 알림"은 경쟁 서비스(Visualping, Distill.io, 커뮤니티 키워드 알림 앱)가 많고 일반 사용자의 지불 의사가 낮아 유료화가 어렵다. **알림 하나가 일감·돈으로 이어지는 사람**에게 좁힌 "지자체 공고 알림"을 상용화 방향으로 잡는다 → 9장.

## 7. 위험과 확인할 것

1. **목록 자동 인식 정확도:** 실제 게시판 10~20곳(구청, 시설관리공단, LH, 학교, 커뮤니티)으로 인식 성공률을 먼저 잰다. 실패하면 "목록에서 글 하나를 눌러 알려주기" 같은 수동 지정 방식을 둔다.
2. **약관·robots.txt:** 자동 수집을 금지하는 사이트는 등록을 막거나 경고한다. 요청 간격을 지키고 User-Agent에 서비스 이름을 밝힌다.
3. **차단:** 같은 IP에서 많은 요청이 가면 막힐 수 있다. URL 단위 캐시로 요청 수를 줄이고, 사이트별 최소 간격을 둔다.
4. **오알림:** 고정 공지 순서 변경, 페이지 넘김, 날짜 표시 변화로 생기는 거짓 알림을 테스트로 막는다.

## 9. 상용화 방향: 지자체 공고 알림

### 9-1. 한 줄 설명

전국 지자체(시·군·구, 시·도) 고시·공고 게시판을 **미리 등록해 두고**, 사용자는 지역과 키워드만 고르면 맞는 공고가 올라올 때 알려준다. 사용자가 URL을 찾아 넣을 필요가 없다.

### 9-2. 누가 돈을 내나

| 대상 | 찾는 공고 | 알림 키워드 예시 | 지불 이유 |
|---|---|---|---|
| 건설·인테리어·조경 업체 | 공사·용역 발주, 소규모 수의계약 공고 | 공사, 용역, 보수, 정비, 수의계약 | 공고 하나가 곧 일감이다 |
| 행사·이벤트·홍보물 업체 | 축제·행사 대행, 인쇄·홍보 용역 | 축제, 행사, 대행, 홍보물 | 지역 행사 공고는 흩어져 있다 |
| 부동산 중개사·투자자 | 도시관리계획, 지구단위계획, 개발행위, 토지 보상 | 도시관리계획, 지구단위, 보상, 실시계획인가 | 개발 정보가 곧 시세 정보다 |
| 소상공인·농가 | 지원사업, 보조금, 시설 개선 지원 | 지원사업, 보조금, 소상공인, 농업인 | 놓치면 수백만 원 손해 |
| 공무직·기간제 구직자 | 지자체 채용 | 채용, 기간제, 공무직 | 기관마다 게시판이 따로 있다 |

- 이미 비슷한 유료 시장이 있다: 나라장터 입찰 알림 서비스, 정부지원사업 알림 서비스. 경쟁 조사 결과 지원사업·입찰은 이미 붐비고, **도시계획·개발·보상 고시의 키워드 알림**이 상대적으로 비어 있다 → 9-8장.

### 9-3. 범용 알림기와 다른 점

| 항목 | 범용 (1~8장) | 지자체 공고 알림 |
|---|---|---|
| 감시 대상 | 사용자가 URL 입력 | 운영자가 미리 등록 (전국 약 260곳 × 고시공고·공지·채용) |
| 사용자 입력 | URL + 키워드 | 지역 + 분야 + 키워드 |
| 서버 비용 | 사용자 수만큼 늘어남 | 게시판 수만큼 고정 (사용자가 늘어도 요청 수 같음) |
| 사이트 개편 대응 | 사용자마다 깨짐 | 운영자가 한 번 고치면 끝 |
| 데이터 활용 | 개인 알림만 | 공고 모음 공개 페이지(검색 유입), 통계, AI 요약 |

### 9-4. 핵심 기능

1. **수집:** 등록된 지자체 게시판을 30분~1시간마다 확인한다. 엔진은 지금 만든 목록 인식·새 글 판단 코드를 그대로 쓴다. 인식이 안 되는 게시판은 사이트별 설정(목록 위치 지정)으로 보완한다.
2. **본문 수집 + 첨부 파일 이름:** 공고는 제목만으로 부족하다(예: "고시 제2026-88호"). 새 글은 본문과 첨부 파일 이름까지 한 번 가져와 키워드를 찾는다.
3. **분류:** 공사·용역 / 도시계획·개발 / 지원사업 / 채용 / 기타. 처음엔 키워드 규칙, 이후 LLM 분류.
4. **알림 설정:** 지역(시·도, 시·군·구 여러 개) + 분야 + 포함·제외 키워드.
5. **알림:** 즉시(유료) 또는 하루 1번 모아 보내기(무료). 이메일 → 웹 푸시 → 카카오 알림톡.
6. **공개 페이지:** "충남 오늘의 공고", "논산시 고시공고 모음"처럼 지역별 공고 목록. 검색 유입과 광고 수익 담당.
7. **AI 요약 (유료):** 공고 본문·첨부에서 사업명, 금액, 기간, 신청 자격, 마감일만 뽑아 3줄로 정리.

### 9-5. 수익 모델 `(가정)`

| 요금제 | 내용 | 가격 |
|---|---|---|
| 무료 | 지역 1곳, 키워드 3개, 하루 1번 모아서 알림 | 0원 |
| 개인 | 전국, 키워드 무제한, 즉시 알림, AI 요약 | 월 5,000~10,000원 |
| 업체 | 담당자 여러 명, 엑셀 내보내기, 지난 공고 검색 | 월 30,000~50,000원 |
| 광고 | 공개 공고 모음 페이지 | 애드센스 (002 모델) |

### 9-6. 위험과 확인할 것

1. **경쟁 서비스:** ~~조사~~ — 완료 (2026-10-08) → 9-8장. 지원사업·입찰은 이미 붐빈다.
2. **공공데이터 대체 가능성:** 공공데이터포털이나 지자체 OpenAPI로 고시공고를 제공하는 곳이 있으면 수집 대신 그것을 쓴다. 공식 데이터가 전국을 다 덮는다면 차별점은 "알림·분류·요약"으로 옮긴다.
3. **저작권·이용 조건:** 공공기관 고시·공고는 공공누리 표시를 확인한다. 공개 페이지에는 제목·요약·원문 링크만 싣고 본문 전체 복제는 하지 않는다.
4. **수집 부담·차단:** 지자체당 1시간에 몇 번 수준이라 부담은 작다. User-Agent에 서비스 이름과 연락처를 밝힌다.
5. **게시판 인식률:** 지자체 홈페이지는 몇몇 CMS 업체 제품을 많이 쓴다 `(가정)`. CMS별 설정을 만들면 여러 곳을 한 번에 덮을 수 있다.

1. **기술 검증:** 충남 15개 시·군의 고시공고·공지사항 게시판 URL 정리 → 목록 인식 성공률 측정. 첫 대상: 논산시 [040102](https://www.nonsan.go.kr/public/html/sub04/040102.html), [040104](https://www.nonsan.go.kr/public/html/sub04/040104.html). (이 클라우드 환경에선 지자체 도메인 접속이 막혀 있어, 도메인 허용 또는 GitHub Actions에서 실행 필요)
2. **기록만 하기:** 2주 동안 수집만 해서 하루 공고 수, 분야별 비율, 오알림을 본다.
3. **공개 페이지:** "충남 오늘의 공고" 페이지를 gh-pages에 올리고 2~4주 방문·검색 유입을 본다 (005와 같은 방식).
4. **지불 의사 확인:** 지역 건설·인테리어 업체, 중개사 5~10곳에 "이런 알림에 월 1만 원 내실래요?"를 직접 묻는다. 2~3곳이 실제로 내겠다고 하면 본격 개발.
5. **확장:** 충남 → 전국 시·군·구, 이메일 알림 → 유료 요금제.

#### MVP 정의 (보상 공고 알림)

1. **수집 대상:** 한국부동산원 보상계획 공고 게시판 + LH·K-water·한국도로공사 보상 공고 + 충남 15개 시·군 고시공고(키워드로 걸러냄)
2. **판별 키워드 사전:** 보상계획, 토지조서, 물건조서, 열람, 사업인정, 실시계획인가, 실시계획 승인, 도시계획시설, 수용재결, 공탁, 공시송달, 지구 지정, 주민 의견 청취
3. **단계 분류:** 제목·본문 키워드로 ①~⑤ 단계를 붙인다
4. **사업 묶기:** 사업명(예: "○○ 도시계획도로 개설공사")이 같거나 비슷하면 하나의 사업 타임라인으로 묶는다
5. **알림:** 지역(시·군) + 단계 + 키워드(동·리 이름, 사업명)
6. **AI 요약:** 사업명, 시행자, 위치(동·리), 편입 면적, 열람 기간·장소, 이의신청 마감일

#### 위험 (추가)

- **개인정보:** 보상계획 공고 첨부(토지·물건조서)에 소유자 이름·주소가 들어가는 경우가 많다. **첨부 내용은 키워드 찾기에만 쓰고 저장·공개하지 않는다.** 공개 페이지에는 사업명·위치·기간·원문 링크만.
- **법률 광고 규정:** 변호사·행정사가 알림을 받아 소유자에게 연락하는 방식은 각 직역의 광고·영업 규정이 적용된다. 서비스는 정보 제공까지만 하고 영업 방식은 사용자 책임으로 약관에 쓴다.
- **누락:** 일간신문에만 나고 온라인 게시판에 없는 공고는 놓친다. "전국 빠짐없이"를 약속하지 않는다.
