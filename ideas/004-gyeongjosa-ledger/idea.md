## 1. 아이디어 개요

### 아이디어명
경조사비 관리 앱 (가칭: 마음장부)

### 한 줄 설명
결혼식·장례식·돌잔치 등에서 **주고받은 경조사비를 사람별로 기록**하고, 다가오는 경조사에 **얼마를 내야 할지 기록을 근거로 알려주는** 모바일 장부 앱.

---

## 2. 해결하려는 문제

경조사비는 "받은 만큼 돌려주는" 문화가 강하지만, 기록이 제대로 남아 있지 않은 경우가 많다.

- 결혼식 방명록·축의금 봉투 정리가 번거롭고, 종이나 엑셀로 흩어져 있다.
- 몇 년 뒤 상대방 경조사가 생겼을 때 **예전에 얼마를 받았는지 기억나지 않는다.**
- 내가 누구에게 얼마를 냈는지도 기록하지 않아 **주고받은 균형**을 알 수 없다.
- 적정 금액(관계, 물가, 참석 여부)에 대한 고민이 매번 반복된다.
- 부모님 세대의 종이 장부는 분실·훼손 위험이 있고 가족이 함께 보기 어렵다.

### 2-1. 누구의 불편인가

| 대상 | 겪는 불편 |
|---|---|
| 결혼 준비/직후 부부 | 축의금 수백 건을 정리하고 답례·감사 인사를 챙겨야 한다. |
| 상을 치른 가족 | 경황이 없는 중에 받은 조의금을 정리해야 하고, 이후 답례가 필요하다. |
| 30~50대 직장인 | 경조사가 잦고, 예전에 받은 금액을 기억해 맞춰 내고 싶다. |
| 부모님 세대 | 수십 년간 종이 장부를 써 왔고, 자녀가 대신 관리해 주길 원한다. |

### 2-2. 문제의 크기 (검증 필요)

- 1년에 참석/송금하는 경조사 횟수: ___ 회 `(설문으로 확인)`
- 결혼식 1회에 받은 축의금 건수: ___ 건 `(인터뷰로 확인)`
- 예전에 받은 금액을 몰라 곤란했던 경험: ___ `(설문으로 확인)`

## 3. 해결 방법

1. **사람(연락처) 등록**: 이름, 관계(가족/친구/직장/지인), 메모
2. **행사 등록**: 내 행사(결혼·장례·돌잔치·개업 등) 또는 상대방 행사
3. **주고받은 내역 기록**: 받은 돈 / 준 돈, 금액, 날짜, 방식(현금·계좌이체·화환), 참석 여부
4. **사람별 장부 보기**: "이 사람에게 받은 총액 / 준 총액 / 차이"
5. **금액 추천**: 상대방 경조사 등록 시 이전 기록과 관계를 근거로 금액 제안
6. **일정 알림**: 다가오는 경조사 D-day 알림, 송금 여부 체크
7. **내보내기**: 엑셀/CSV 백업, 답례 명단 출력
8. **이미지로 지난 기록 등록**: 방명록·장부·이체 내역 사진을 텍스트로 바꿔 한 번에 등록 (아래 3-2)

### 3-1. 핵심 설계 원칙

- **개인정보는 기기 안에 먼저 저장한다.** (타인 이름+금액은 민감 정보) 서버 백업·가족 공유는 사용자가 선택할 때만.
- **입력이 가장 쉬워야 한다.** 결혼식 직후 수백 건을 넣는 상황을 기준으로 설계한다. (빠른 연속 입력, 엑셀 붙여넣기)
- **금액 추천은 근거를 보여준다.** "2023년에 10만원 받음" 처럼 이유를 함께 표시하고, 결정은 사용자가 한다.
- **돈을 직접 보내지 않는다.** (MVP) 송금은 은행 앱으로 연결만 하고 결제·송금 규제 대상이 되지 않게 한다.
- **이미지 인식 결과는 바로 저장하지 않는다.** 사용자가 확인·수정한 뒤에만 장부에 등록한다.

### 3-2. 이미지로 지난 기록 등록 (OCR)

지난 기록은 대부분 종이나 사진으로 남아 있다. 하나씩 손으로 옮겨 적는 것이 가장 큰 진입 장벽이므로, **사진을 찍거나 불러오면 텍스트로 바꿔 장부에 일괄 등록**한다.

#### 대상 이미지

| 이미지 | 예상 인식 난이도 | 비고 |
|---|---|---|
| 은행 앱 이체 내역 캡처 | 쉬움 (인쇄 글씨, 형식 일정) | "김민수 100,000" 형태. 날짜·금액이 정확하다. |
| 엑셀·메모 앱 화면 캡처 | 쉬움 | 표 형태라 이름·금액 분리가 쉽다. |
| 축의금 정리 대장 (인쇄 양식에 손글씨) | 보통 | 예식장·장례식장이 제공하는 양식 |
| 부모님 종이 장부 (손글씨) | 어려움 | 필체·줄 맞춤이 제각각 |
| 축의금 봉투 (세로 손글씨, 한자 이름) | 어려움 | 장수가 많아 연속 촬영 필요 |

#### 처리 흐름

1. 행사 선택 (예: 내 결혼식 2024-05-18) 후 `사진으로 등록`
2. 사진 촬영 또는 앨범에서 여러 장 선택
3. 텍스트 인식 (OCR)
4. **이름 / 금액 / 메모(관계·소속)** 로 자동 분리
   - 금액 정규화: `10만`, `100,000`, `拾萬원` → `100000`
   - 이름 옆의 소속(`○○회사`, `대학 동기`)은 관계 후보로 제안
5. **확인 화면**: 원본 이미지와 인식 결과를 나란히 보여주고, 인식 신뢰도가 낮은 칸은 강조 표시
6. 기존 사람과 이름이 같으면 "같은 사람인가요?" 확인 후 연결 (동명이인 대비)
7. 확정한 줄만 장부에 일괄 등록, 합계(건수·총액)를 원본과 비교할 수 있게 표시

#### 기술 선택지 (가정)

| 방식 | 장점 | 단점 |
|---|---|---|
| 기기 내 OCR (예: Google ML Kit 한국어 텍스트 인식) | 무료, 이미지가 기기를 벗어나지 않음 (개인정보) | 손글씨 인식률이 낮을 수 있음 |
| 클라우드 OCR (예: 네이버 CLOVA OCR, Google Cloud Vision) | 손글씨·표 인식률이 높음 | 건당 비용, 이미지를 외부로 전송 → 사용자 동의 필요 |
| 멀티모달 AI (이미지 → 이름·금액 JSON 직접 추출) | 소속·관계 분리, 금액 표기 정규화까지 한 번에 | 비용, 외부 전송, 결과 검증 필요 |

- 기본은 **기기 내 OCR**, 손글씨처럼 인식이 어려운 이미지는 사용자 동의를 받아 **클라우드/AI 인식**을 쓰는 2단 구조를 우선 검토한다.
- 인식된 금액 합계는 코드가 계산한다. (AI에게 계산을 맡기지 않는다 — 001과 같은 원칙)

## 4. 핵심 가치

### 사용자 입장
"얼마 받았더라?"를 고민하지 않고, 받은 마음을 빠짐없이 기억하고 돌려줄 수 있다.

### 서비스 입장
경조사는 평생 반복되는 이벤트이므로 한 번 기록을 쌓으면 **오래 쓰는 앱**이 된다. 경조사 관련 서비스(모바일 청첩장, 화환, 답례품)와 자연스럽게 연결된다.

### 장기 목표
개인 장부 → 가족 공동 장부 → 경조사 전반(초대장, 화환, 답례품)을 잇는 플랫폼.

## 5. 예상 사용자

### 주요 사용자
- 결혼을 앞두었거나 막 결혼한 부부
- 상을 치른 유가족
- 경조사가 잦은 30~50대 직장인
- 부모님 장부를 대신 관리하는 자녀

### 첫 번째 타깃 (가정)
**결혼식을 막 마친 신혼부부**. 축의금 정리라는 명확하고 급한 작업이 있고, 이후 수년간 "돌려줄 때" 다시 앱을 찾는다.

## 6. 핵심 기능

### MVP
- 사람 등록 (직접 입력 + 휴대폰 연락처 불러오기)
- 행사 등록 (내 행사 / 상대 행사)
- 받은 돈·준 돈 기록, 빠른 연속 입력
- **이미지로 지난 기록 등록 (OCR)**: 이체 내역·엑셀 캡처·인쇄 대장 우선, 확인 화면 후 일괄 등록
- 사람별 장부 (받은 총액, 준 총액, 차이)
- 행사별 합계 (예: 내 결혼식 총 축의금, 건수)
- 검색·필터 (이름, 관계, 기간)
- 다가오는 경조사 알림
- 엑셀/CSV 내보내기·가져오기
- 기기 내 저장 + 수동 백업

### MVP에서 제외 (후속 단계)
- 손글씨 장부·봉투 인식 고도화 (클라우드/AI 인식, 연속 촬영)
- 모바일 청첩장·부고 링크에서 일정 자동 추출
- 가족 공동 장부 (부부, 부모-자녀 공유)
- 관계·지역·물가 기반 **적정 금액 통계**
- 감사 문자 일괄 작성 (AI 문구 생성)
- 화환·답례품 제휴, 송금 연동

## 7. 사용 예시

### 상황
2년 전 결혼식에서 대학 동기 김민수에게 축의금 10만원을 받았다. 오늘 김민수의 청첩장이 왔다.

### 흐름
1. 앱에서 `+ 경조사` → 김민수 / 결혼식 / 2026-11-21 입력
2. 앱이 기록을 보여준다.

```text
김민수 (대학 동기)
- 2024-05-18 내 결혼식: 10만원 받음 (참석)
- 준 내역 없음
추천: 10만원 (받은 금액과 동일) · 식사 참석 시 일반적으로 10만원 이상
```

3. 송금 후 `준 돈 10만원, 계좌이체` 체크 → 장부 균형 0원

### 사람별 장부 예시

| 이름 | 관계 | 받은 총액 | 준 총액 | 차이 |
|---|---|---:|---:|---:|
| 김민수 | 대학 동기 | 100,000 | 100,000 | 0 |
| 박지영 | 직장 | 50,000 | 0 | +50,000 |
| 이현우 | 친척 | 300,000 | 200,000 | +100,000 |

## 8. 기존 대안과 차별점

### 8-1. 지금은 어떻게 해결하나

| 대안 | 한계 |
|---|---|
| 종이 방명록·장부 | 검색이 안 되고 분실 위험, 가족 공유 불가 |
| 엑셀/구글 시트 | 모바일 입력이 불편, 알림·추천 없음 |
| 휴대폰 메모·은행 이체 내역 | 흩어져 있어 사람별로 모아 보기 어려움 |
| 기존 경조사 장부 앱 | 기능·평점·사용자 불만 **조사 필요** |

### 8-2. 이 서비스의 차별점 (가정)
- **주고받은 양방향 장부**: 사람별 균형을 한눈에
- **근거 있는 금액 추천**: 과거 기록 기반
- **대량 입력에 최적화**: 결혼식 직후 수백 건 입력, 엑셀 붙여넣기
- **사진 한 장으로 지난 기록 이전**: 종이 장부·이체 내역을 텍스트로 바꿔 바로 장부화 → 처음 쓰는 날부터 과거 기록이 채워진 장부
- **개인정보는 기기 우선 저장**

## 10. 검증 계획

1. **기존 앱 조사**: 앱스토어에서 경조사 장부 앱 3~5개 설치, 리뷰의 불만 사항 정리
2. **인터뷰/설문**: 최근 1년 내 결혼한 사람 5~10명 — 축의금 정리 방법, 걸린 시간, 불편한 점
3. **엑셀 템플릿 배포**: 앱을 만들기 전에 "축의금 정리 엑셀"을 무료 배포하고 다운로드 수로 수요 확인
4. **OCR 샘플 테스트**: 실제 이체 내역 캡처·축의금 대장·종이 장부 사진을 각 10장 이상 모아 기기 내 OCR / 클라우드 OCR 인식률 비교
5. **웹 프로토타입**: 기기 저장 기반 PWA로 핵심 흐름(기록 → 사람별 장부 → 추천) 시연

### 성공 기준 (가정)
- 인터뷰 대상 중 3명 이상이 "결혼식 끝나고 바로 쓰고 싶다"고 답한다.
- 엑셀 템플릿 또는 프로토타입 사용자 중 일부가 실제 데이터를 입력해 본다.
- 인쇄 글씨(이체 내역·대장) 이미지에서 이름·금액 인식 정확도 95% 이상 `(가정)`

## 11. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 타인 이름·금액 등 개인정보 취급 | 기기 내 저장 기본, 백업 시 암호화, 개인정보처리방침 명시 |
| 입력이 귀찮아 이탈 | 연속 입력 UI, 엑셀 가져오기, 이미지 OCR 등록 |
| 손글씨 인식률이 낮아 수정이 더 번거로움 | 인쇄 글씨부터 지원, 신뢰도 낮은 칸 강조, 원본 이미지 나란히 보기, 어려운 이미지만 클라우드 인식 |
| 이미지(타인 이름·금액)를 외부 서버로 전송 | 기본은 기기 내 OCR, 외부 전송 시 명시적 동의, 이미지 저장하지 않음 |
| 클라우드 OCR 비용 | 무료 사용 한도 설정, 고정밀 인식은 프리미엄 |
| 1년에 몇 번 쓰지 않는 앱 | 알림, 다가오는 경조사 관리로 재방문 유도 |
| 기존 앱과 차별화 부족 | 검증 1단계에서 기존 앱 불만을 먼저 파악 |
| 금액 추천에 대한 거부감 ("돈 계산하는 느낌") | 추천은 선택 기능, 표현을 "기록 참고"로 부드럽게 |
| 송금 기능 시 금융 규제 | MVP는 송금 미포함, 은행 앱 연결만 |
