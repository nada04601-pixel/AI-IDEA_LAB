# 벤치마킹: 클리피(Clipy, clipy.kr)

- 작성일: 2026-10-21
- 목적: 유튜브 채널 분석 서비스 "클리피"의 기능을 정리하고, [005 오늘의 떡상 쇼츠 분석기](idea.md)에 가져올 기능을 고른다.
- `(가정)` 표시는 아직 확인되지 않아 임시로 정한 내용입니다.

> **조사 범위:** 작성 환경에서는 clipy.kr에 직접 접속하지 못했다. 사용자가 저장해 준 첫 화면 HTML(2026-10-21)과 검색 결과로 작성했다. 이 HTML은 React/Vite 앱의 껍데기라 실제 메뉴·요금·지표 산식은 JS 번들 안에 있어 아직 확인하지 못했다 (7장 체크리스트). 다만 검색엔진용 본문(`<noscript>`)에 "실제 화면과 같게 유지"한다는 주석과 함께 기능 목록이 들어 있어, 아래 2장은 그 내용을 그대로 옮겼다.

## 1. 클리피 한 줄 요약

> "클리피는 10만개 유튜브 채널 데이터를 **매일 수집·분석**해 트렌딩 채널, 타율 기반 인사이트, 채널 그룹 비교를 한 화면에서 보여주는 유튜브 채널 분석 서비스입니다." — 사이트 본문

- 슬로건: "채널 성장에 필요한 모든 것 — 매일 수작업으로 확인하던 데이터를 자동으로 수집하고 분석해드려요."
- 운영: 페이븐(Paven), 개인사업자. 서비스 페이지: 홈 · 이용약관(`/terms`) · 개인정보처리방침(`/privacy`)
- 핵심 차별점은 **"채널 10만 개를 매일 미리 모아 두는 DB"** 다. 사용자가 검색할 때마다 API를 부르지 않고, 쌓아 둔 데이터로 순위·비교를 바로 보여 준다.

## 2. 클리피 기능 (사이트 본문 기준)

| # | 기능 (사이트 문구) | 해석 |
|---|---|---|
| 1 | **벤치마킹 채널 그룹 자동 수집** — "벤치마킹 채널을 그룹으로 묶어 매일 자동 수집 — 구독자 변화, 신규 영상, 조회수 추이" | 내가 참고하는 경쟁 채널을 그룹으로 등록하면 매일 구독자 증감·새 영상·조회수 변화를 기록해 준다. **매일 일일이 들어가 보던 일을 대신해 주는 것**이 핵심 가치 |
| 2 | **급성장 채널 선별** — "매일 10만개 채널을 분석해 급성장 채널 5,000개 선별" | 전체 DB 중 성장률 상위 5% 정도를 "트렌딩 채널"로 매일 뽑는다. 성장 기준(구독자? 조회수? 기간?)은 미확인 |
| 3 | **돌연변이 영상 탐지** — "갑자기 터진 '돌연변이' 영상 탐지" | 채널 평소 조회수보다 크게 터진 영상(아웃라이어)을 찾는다. 보통 `영상 조회수 ÷ 채널 최근 영상 조회수 중앙값`으로 계산한다 `(가정 — 산식 미확인)` |
| 4 | **타율 TOP 채널 랭킹** | "타율" = 채널이 올린 영상 중 평소 이상으로 터진 영상의 비율로 보인다 `(가정)`. 타율이 높은 채널, 즉 꾸준히 잘 터뜨리는 채널 순위 |

**가입·요금 흐름**
- "3분이면 시작할 수 있어요" — **카카오 로그인 한 번**으로 모든 기능 체험
- **카드 등록 없이 무료로 시작** → 무료 체험 후 유료 전환 구조로 보인다. 체험 기간·가격은 미확인

**기술·SEO에서 참고할 점** (002·005 수익화에 그대로 쓸 수 있다)
- React/Vite 한 페이지 앱 + Pretendard 폰트
- JS를 실행하지 않는 네이버 검색 로봇(Yeti)을 위해 `<noscript>`에 실제 화면과 같은 본문을 넣었다. 화면과 내용이 다르면 클로킹(속임수)으로 처리되므로 같게 유지한다는 주석이 있다.
- 제목·설명에 한글 "클리피"와 영문 "Clipy"를 함께 넣어 네이버 한글 검색에도 잡히게 했다.
- schema.org 구조화 데이터(Organization·WebSite·SoftwareApplication), Open Graph·트위터 카드, 네이버 서치어드바이저 소유확인을 넣었다.

**관찰**
- 005는 이미 클립스코프의 "시간당 조회수 실측"과 같은 기능이 있다. 빠진 것은 **채널 단위 분석**(타율·채널 비교·채널 순위)이다.
- 유료 서비스들의 공통 축은 "조회수 절댓값"이 아니라 **"채널 평소 대비 몇 배 터졌나"** 다 (클리피의 "돌연변이 영상"). 구독자가 적은 채널의 대박 영상을 찾는 것이 크리에이터에게 가장 쓸모 있는 정보다.
- 클리피가 돈을 받는 부분은 **"내 벤치마킹 채널을 매일 대신 지켜봐 주는 것"** 이다. 이건 서버에 매일 쌓는 기록이 있어야 해서, 브라우저만으로 돌아가는 005 직접 검색 모드로는 따라 하기 어렵다.

## 4. 005에 가져올 기능 (우선순위)

| 순위 | 기능 | 설명 | 난이도 |
|---|---|---|---|
| 1 | **돌연변이 배지 (영상 타율)** | 떡상 쇼츠마다 "채널 평균의 N배" 표시. 순위를 이 값으로도 정렬 | 낮음 |
| 2 | **채널 타율 카드** | 쇼츠를 누르면 그 채널의 구독자·최근 영상 중앙 조회수·"평균 2배 이상 터진 영상 비율" | 중간 |
| 3 | **채널 DB 누적** | 수집 때 만난 채널을 계속 쌓는다 (눈덩이 방식). 일별 구독자·조회수 기록 → 급성장 채널 순위 | 중간 |
| 4 | **채널 그룹 비교** | 직접 검색 모드(내 API 키)에서 채널 여러 개를 골라 표·차트로 비교. 그룹은 브라우저에 저장. 클리피처럼 "매일 자동 기록"은 서버·로그인이 필요하므로, 1차는 "열 때마다 지금 값 비교 + 지난번 연 때와 차이"로 대신한다 | 중간 |
| 5 | **니치 포화도** | 키워드별 "영상 수 대비 떡상 비율"로 이 주제가 붐비는지 표시 (클립스코프 참고) | 높음 |

### 지표 정의 (안)

```text
채널 기준 조회수   = 채널 최근 영상 N개(기본 15개, 쇼츠만) 조회수의 중앙값
영상 타율(배수)    = 영상 조회수 ÷ 채널 기준 조회수
채널 타율(%)       = 최근 N개 중 영상 타율 ≥ 2.0 인 영상의 비율
구독자 대비 조회율 = 채널 기준 조회수 ÷ 구독자 수
```

- 평균 대신 **중앙값**을 쓴다. 한 개의 초대박 영상이 기준을 끌어올리지 않게 하기 위해서다.
- 업로드 후 48시간이 안 된 영상은 조회수가 아직 덜 쌓였으므로 기준 계산에서 뺀다.

## 5. 데이터 확보 방법 (YouTube Data API 할당량 기준)

| 호출 | 비용 | 용도 |
|---|---|---|
| `channels.list` (id 50개 묶음) | 1단위 / 50채널 | 구독자·총조회수·업로드 재생목록 ID |
| `playlistItems.list` (업로드 목록) | 1단위 / 채널 | 최근 영상 50개 ID |
| `videos.list` (id 50개 묶음) | 1단위 / 50영상 | 영상 조회수·길이 (쇼츠 판별) |

- 채널 1개 타율 계산 ≈ **약 2단위**. 매시간 새로 만나는 채널 ~100개만 처리하면 시간당 ~200단위, 하루 ~4,800단위.
- 현재 005가 하루 약 7,300단위를 쓰므로 합치면 하루 10,000단위 한도를 넘는다. → **채널 타율은 한 번 계산하면 24시간 캐시**하고, 처음 본 채널만 새로 계산해 하루 2,500단위 안으로 맞춘다.
- 클리피처럼 10만 채널을 매일 갱신하는 것은 무료 할당량으로는 불가능하다 (`channels.list`만 해도 2,000단위지만, 최근 영상까지 보려면 채널당 1단위 이상 → 10만 단위). 할당량 증설 신청 또는 "구독자 통계만 매일, 영상 목록은 주 1회"로 나눠야 한다.

## 6. 구현 단계 (제안)

1. **1단계 — 영상 타율 배지:** `scripts/collect.mjs`에 채널 기준 조회수 계산 추가, 결과는 `channels.json`(24시간 캐시)에 저장. 공개 페이지에 "평균의 N배" 배지와 정렬 옵션.
2. **2단계 — 채널 카드 + DB 누적:** gh-pages에 `channels/` 데이터 누적, 일별 구독자 스냅샷으로 "급성장 채널" 탭.
3. **3단계 — 그룹 비교:** `search.html`에 채널 추가·그룹 저장·비교표.
4. **4단계 — 니치 포화도·AI 요약:** 005 다음 단계 6번(AI 요약)과 합친다.

## 7. 리스크

- **YouTube API 약관:** API 데이터는 30일 안에 갱신하거나 지워야 한다. 채널 DB를 "누적"할 때 오래된 통계는 지우거나 다시 가져와야 하고, 자체 계산한 지표(타율)도 원본 데이터 보관 규칙을 따르는지 확인 필요.
- **스크래핑 금지:** 경쟁 서비스의 데이터를 긁어 오지 않는다. 기능 아이디어만 참고한다.
- **클리피는 AI 접근을 막는다:** robots.txt(2026-10-14 기준)에서 ClaudeBot·Claude-User·GPTBot 등 AI 봇의 "학습·대신 읽기"를 전부 막고, nginx도 같은 규칙으로 403을 준다. 그래서 AI 도구로 사이트를 읽어 분석하지 않고, 사람이 직접 본 화면(캡처·복사한 글)으로만 벤치마킹한다.
- **이름·디자인:** 클리피의 화면·문구를 그대로 베끼지 않는다.
