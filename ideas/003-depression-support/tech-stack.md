## 2. 데이터 구조 (IndexedDB)

### `entries` — 기분 기록

| 필드 | 타입 | 설명 |
|---|---|---|
| id | string (UUID) | 기록 ID. 백업 합치기 시 중복 판정에 사용 |
| date | string `YYYY-MM-DD` | 기록 날짜 (사용자 기기 시간대 기준). 인덱스 |
| time | string `HH:mm` | 기록 시각 |
| mood | 1 ~ 5 | 기분 5단계 (screens.md 4-3) |
| memo | string | 한 줄 메모, 최대 100자, 선택 |
| tags | string[] | 고정 태그 6개 중 선택 |
| createdAt | number | 생성 시각 (ms) |
| updatedAt | number | 수정 시각 (ms) |

### `settings` — 설정 (키-값)

| 키 | 값 |
|---|---|
| `onboardingDone` | boolean |
| `reminderEnabled`, `reminderTime` | boolean, `HH:mm` |
| `visitNote` | 진료 때 하고 싶은 말 (S-04 자동 저장) |
| `reportIncludeMemo` | boolean (기본 true) |

- 날짜를 `YYYY-MM-DD` 문자열로 저장해 시간대 변환 문제를 피한다.
- 스키마 변경 시 Dexie의 `version()` 마이그레이션을 사용한다.

## 3. 기록 알림 — 중요한 제약

**PWA는 "매일 오후 9시"처럼 기기에서 알림을 예약할 수 없다.** 이를 위한 브라우저 API(Notification Triggers)는 표준화되지 않고 중단되었다. PWA에서 정해진 시각에 알림을 보내려면 **서버가 Web Push를 보내야 한다.**

이는 idea.md의 "서버 없음" 원칙과 충돌하므로 선택이 필요하다.

| 방법 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 최소 푸시 서버 | 서버에는 **푸시 구독 정보 + 알림 시각만** 저장. 기분 기록은 여전히 기기에만 저장 | PWA 단계에서 알림 효과를 검증할 수 있다 | 서버 운영 필요. "이 서비스를 쓴다"는 사실 자체가 서버에 남으므로 개인정보 처리방침 필요 |
| B. 앱 단계로 미룸 | PWA 단계에서는 알림 없이 검증, 2단계 Capacitor 앱의 **로컬 알림**으로 해결 | 서버가 끝까지 필요 없다. 로컬 알림은 기기에서 예약되므로 개인정보 부담이 없다 | 1단계에서 "알림이 기록 지속률에 주는 영향"을 측정할 수 없다 |

**잠정 결정: B** `(가정)`

> **2026-10-07 갱신:** Capacitor 안드로이드 앱을 바로 만들 수 있게 되어 B를 앞당겨 적용했다. 알림은 `@capacitor/local-notifications`로 기기에서 예약하며 서버는 여전히 없다. 테스트는 **안드로이드 앱 중심**으로 하고, 웹은 가이드 콘텐츠·유입 창구로 둔다. 이로써 "알림이 기록 지속에 주는 영향"도 1단계에서 측정할 수 있다.

- 이 서비스는 신뢰가 핵심이고, "기록은 서버로 보내지 않아요"를 첫 화면에서 약속한다(screens.md S-01). 서버를 하나 두는 것만으로 이 설명이 복잡해진다.
- 1단계는 **알림 없이도 다시 오는지**를 보는 더 엄격한 검증이 된다. 지표가 기준에 못 미치면 알림을 원인 후보로 두고 2단계를 앞당긴다.
- 따라서 프로토타입에서 S-01의 알림 설정과 S-09의 알림 항목은 **"앱 출시 후 제공"으로 표시**한다.

## 4. 리포트 PDF

- S-05 리포트 화면에 인쇄용 CSS(`@media print`)를 적용해 A4 한 장으로 정리한다.
- [PDF 저장] → `window.print()` → 사용자가 "PDF로 저장"을 선택.
- 서버를 거치지 않는다.
- iOS 홈 화면 PWA(standalone)에서 `window.print()`가 동작하는지 `(확인)`. 안 되면 대안: html2canvas + jsPDF로 이미지 PDF 생성.

## 5. 오프라인 / 캐시

- 앱 화면, 가이드 콘텐츠, 도움받을 곳 전화번호는 모두 빌드에 포함되어 오프라인에서 열린다.
- 서비스 워커는 `autoUpdate`로 두고, 새 버전이 있으면 다음 실행 때 적용한다.
