## 1. 아이디어 개요

### 아이디어명
마음기록 + 첫 진료 길잡이 `(가칭)`

### 한 줄 설명
우울감을 겪는 사람이 버튼 하나로 기분을 기록하고, 그 기록을 들고 첫 진료·상담까지 갈 수 있게 돕는 기록·연결 도구.

### 통합 배경
초기 후보 6종(부록 참고) 중 **A(초저부담 기분 기록)**와 **C(병원·상담 연결 도우미)**를 하나로 묶었다.

- C로 병원을 찾고 예약할 용기를 얻고, A로 쌓은 기록을 진료 때 보여준다. **C의 "첫 진료 때 할 말"을 A의 기록이 채운다.**
- C만 있으면 병원을 찾은 뒤 앱을 지울 이유가 생긴다. A가 붙어 있으면 진료가 시작된 뒤에도 계속 쓴다. (사용자 유지)

---

## 2. 해결하려는 문제

| 대상 | 겪는 불편 |
|---|---|
| 우울감을 느끼지만 아직 병원에 가지 않은 사람 | 어디로 가야 할지, 비용이 얼마인지, 가서 무슨 말을 해야 할지 몰라 미룬다. |
| 진료·상담을 받고 있는 사람 | 진료 때 "요즘 어땠어요?"라는 질문에 지난 몇 주를 떠올려 설명하기 어렵다. |
| 기존 기분 기록 앱 사용 경험자 | 입력할 게 많고, 기록을 빠뜨리면 죄책감이 들어 포기한다. `(가정)` |

---

## 3. 핵심 설계 원칙

- **입력이 적어야 한다.** 기록은 3초 안에 끝나야 한다. 메모는 선택이다.
- **실패해도 죄책감이 들지 않아야 한다.** 연속 기록(streak), 빠진 날 강조, 독촉 알림을 만들지 않는다.
- **치료를 대신한다고 말하지 않는다.** "기록·관리·연결 도구"로 포지셔닝한다.
- **위기 대응은 처음부터 넣는다.** 모든 화면에서 도움받을 곳(자살예방상담전화 109 등)에 한 번에 갈 수 있다.
- **데이터는 기기에 저장한다.** MVP는 서버에 기분 기록을 저장하지 않는다.

## 4. 플랫폼 전략

### 4-1. 판단

| 기능 | 웹 적합도 | 앱 적합도 | 이유 |
|---|---|---|---|
| 기분 기록 (A) | 낮음 | **높음** | 매일 쓰는 기능이라 푸시 알림과 홈 화면 아이콘이 핵심이다. 브라우저를 열어 들어오는 습관은 만들기 어렵다. |
| 첫 진료 가이드 (C) | **높음** | 보통 | "정신과 첫 진료", "심리상담 바우처" 같은 검색으로 사람이 들어온다. 웹 콘텐츠가 **유입 창구** 역할을 한다. |

결론: **서비스의 본체(기록)는 앱이 맞다.** 다만 처음부터 네이티브 앱을 만들지 않고, 웹 기술로 앱처럼 쓰는 단계를 거친다.

### 4-2. 단계

| 단계 | 형태 | 목적 |
|---|---|---|
| 1단계 | **PWA (설치형 웹앱)** + 가이드 웹페이지 | 웹 개발 역량으로 빠르게 검증. 홈 화면 설치, 푸시 알림, 기기 내 저장(IndexedDB) 가능. 링크 하나로 테스트 사용자 모집. |
| 2단계 | 앱 스토어 출시 (Capacitor 등으로 PWA 래핑) | 1단계 지표가 성공 기준을 넘으면 진행. 기존 코드를 대부분 재사용. |
| 3단계 | 필요 시 네이티브 전환 | 위젯, 고급 알림 등 래핑으로 부족한 기능이 생길 때만 검토. |

### 4-3. 확인할 것

- iOS는 홈 화면에 설치한 PWA에서만 웹 푸시가 동작한다(iOS 16.4 이상). 설치 안내 화면이 필요하다. `(실제 기기에서 확인)`
- 1단계에서 "알림을 켠 사용자"와 "안 켠 사용자"의 기록 지속률을 비교하면, 앱 전환이 실제로 필요한지 판단할 수 있다.

## 5. MVP 기능 범위

### 5-1. 포함

**기분 기록 (A)**

| 기능 | 내용 |
|---|---|
| 하루 기분 기록 | 5단계 이모지 중 하나 선택. 하루 여러 번 기록 가능. |
| 선택 메모 | 한 줄 메모(선택). 수면, 식사 등 간단한 태그(선택). |
| 기록 달력 | 월별 달력에 기분 색으로 표시. 빠진 날은 강조하지 않는다. |
| 기록 알림 | 사용자가 정한 시간에 하루 1회. 끌 수 있고, 기록을 안 해도 다시 독촉하지 않는다. |

**첫 진료 길잡이 (C, 가볍게)**

| 기능 | 내용 |
|---|---|
| 첫 진료 가이드 | 정신건강의학과 / 상담센터 차이, 첫 방문 절차, 대략적인 비용, 기록이 남는지 등 자주 묻는 질문. (정적 콘텐츠) |
| 무료·지원 제도 안내 | 정신건강복지센터, 국가 심리상담 바우처 등 공식 안내 페이지로 링크. **자체 병원 DB는 만들지 않는다.** |
| 예약 전화 대본 | 전화로 예약할 때 할 말 예시. |

**연결 기능 (A+C)**

| 기능 | 내용 |
|---|---|
| 첫 진료 준비하기 | 최근 2주 기분 요약 + "하고 싶은 말" 메모를 한 장으로 정리. |
| 진료용 리포트 | 위 내용을 PDF 또는 화면으로 출력. 진료실에서 보여주기 용도. |

**공통**

| 기능 | 내용 |
|---|---|
| 도움받을 곳 | 모든 화면에서 접근 가능한 버튼. 자살예방상담전화 109, 정신건강위기상담 등 연결. |
| 기기 내 저장 | 기록은 기기에만 저장. 회원가입 없음. |
| 백업 내보내기 | 기록을 파일로 내보내기/가져오기 (기기 변경 대비). |

### 5-2. MVP에서 제외 (후속 단계)

- 위치 기반 병원 검색, 자체 병원 DB
- 회원가입, 서버 저장, 기기 간 동기화
- 복약 관리 (후보 D)
- 보호자 공유 기능 (후보 E)
- 커뮤니티 (후보 F)
- 작은 할 일 투두 (후보 B)
- AI 분석, 챗봇 상담

### 5-3. 화면 목록 (초안)

> 상세 설계는 [screens.md](screens.md) 참고. 화면설계에서 "첫 실행 안내" 화면이 추가되었다.

1. 홈 (오늘 기분 기록 버튼)
2. 기록 달력
3. 첫 진료 준비하기 / 리포트
4. 첫 진료 가이드 (가이드 목록 → 상세)
5. 도움받을 곳
6. 설정 (알림 시간, 백업, 설치 안내)

## 6. 수익 모델 (가정)

MVP 단계에서는 수익화하지 않는다. 신뢰가 핵심인 영역이라 초기 광고는 피한다.

- 후보: 고급 리포트·장기 통계 등 프리미엄 기능 / 기관(상담센터, 기업 EAP) 제휴
- 가이드 웹페이지의 검색 유입은 수익보다 **사용자 유입 경로**로 활용한다.

---

## 7. 검증 계획

1. **당사자·전문가 피드백**: 경험자 3~5명, 가능하면 정신건강 전문가 1명에게 화면 초안을 보여준다.
2. **PWA 테스트 배포**: 링크로 테스트 사용자 모집, 2~4주 사용.
3. **지표 확인**: 기록 지속률, 알림 사용 여부별 차이, 리포트 사용 여부.

### 성공 기준 (가정)

- 테스트 사용자 중 30% 이상이 2주 후에도 주 3회 이상 기록한다.
- 리포트를 실제 진료·상담에 가져간 사례가 1건 이상 나온다.

## 8. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 위기 상황 사용자 | 모든 화면에 도움받을 곳 연결. 메모에 위험 표현이 있을 때 안내를 띄우는 방식은 전문가 의견을 받아 결정. |
| 의료기기 규제 | "치료·개선" 표현 금지. 기록·안내 도구로만 표방. |
| 민감정보 (개인정보보호법) | 서버 저장 없음. 서버를 쓰게 되면 별도 동의 절차 설계. |
| 가이드 정보가 오래됨 | 링크 위주로 구성하고, 비용·제도 정보에는 기준일을 표시. |
| 웹에서 기록 습관이 안 생김 | PWA 설치 + 알림 유도, 지표가 나쁘면 앱 스토어 출시 앞당김. |
